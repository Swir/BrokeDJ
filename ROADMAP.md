## Audio quality and long-track hardening in progress

The original linear rate converter has been replaced in development by a hybrid path: four-point Catmull-Rom interpolation where the effective source step does not require downsampling, and a prepared 24-tap Blackman-windowed sinc kernel selected from a finite cutoff/phase lookup bank when speed-up/downsampling needs anti-alias filtering. Kernel generation is outside the realtime callback. Play/pause/seek, whole-track loop wraparound and streamed starvation/refill boundaries use short de-click transitions. Playback-rate targets, headphone cue switching/level and deck EQ/echo/drive controls are smoothed rather than applying abrupt sample-to-sample jumps.

Large tracks no longer require one decoded stereo allocation for the full file. The development path uses a fixed-size stream cache populated by a background JUCE reader, with small files retaining the simpler in-memory path. After a seek, the reader prioritizes the exact requested chunk and its immediate previous/next neighbours before deeper forward read-ahead, then skips invalid chunks beyond EOF so end-of-track windows cannot create a false-work busy loop. Cache misses request the new source region and return bounded silence instead of doing I/O in the callback. Sparse waveform preview generation reads bounded windows off the audio thread instead of allocating the full decoded track.

Lock-free diagnostics track failed cache reads, the latest missed frame and collapsed starvation/refill episodes. Continuous missing data counts as one starvation episode until a complete interpolation frame becomes readable again. The same prepared transition window fades toward silence on starvation and fades recovered audio back in. Deterministic tests exercise a virtual 90-minute stream, repeated distant seeks, whole-track loop wrap and intentional starvation/refill recovery without allocating full-track audio.

The decoder/read-ahead adapter is separately testable with generated WAV/AIFF/FLAC/OGG data plus an original synthetic MP3 fixture, forced-streaming coverage, Unicode paths, invalid files, cancellation and controlled slow-reader behavior. Objective offline render tests measure rate-conversion frequency error/residual/DC/level, adjacent-sample transition deltas and anti-alias passband/stopband behavior across 48 kHz 1.5x, 44.1→48 kHz 1.5x, 96→48 kHz and 192→48 kHz paths. A separate realtime-contract target verifies zero heap allocation/deallocation in measured callback windows and records representative Catmull-Rom/sinc callback cost as diagnostic evidence. Windows development artifacts retain these measurements in `AUDIO-DIAGNOSTICS.txt`; shared-runner timing is not a performance certification.

The opt-in time-stretch/key-lock stack now reaches the native application lifecycle without replacing ordinary playback. Its JUCE-independent layers cover processor configuration/latency metadata, bounded fractional deck clocking, exact bounded reads from real in-memory or streamed BrokeDJ sources, explicit conversion from stretched source-rate output to device-rate output through a bounded FIFO, Engine-facing lifecycle staging, deck-owned path selection and a two-slot owner handoff. `Engine::process()` can consume the qualified optional source before the existing EQ/FX/gain/cue/crossfader/master/meter chain, while any refusal immediately uses the built-in production rate converter.

When the optional prototype is compiled, the real JUCE app can instantiate and manage those owners only behind `--key-lock-research`. Device prepare/release installs and removes the non-owning Engine renderers while callbacks are stopped; a successfully submitted immutable clip is bound to the lifecycle owner; the message-thread/timer service performs off-callback staging. Live seek, whole-track-loop or playback-rate changes immediately disarm the optional path and keep normal production playback audible until the deck is paused and safely restaged. The app still exposes no key-lock button and does not present this path as release-ready.

The bridges consume caller-provided production fallback samples, keep audible transport separate from prefetch, expose algorithm-latency metadata and fail back rather than emitting stale stretch/FIFO data after bypass/discontinuity/control changes. The deck selector owns off-callback stage/disarm intent and adds a short prepared de-click when the selected path changes. `EngineKeyLockDeckOwner` prepares and stages an inactive source slot off callback, publishes only the completed snapshot, returns `busy` instead of touching a slot retained by an in-flight callback and can disarm fail-closed so later blocks immediately use ordinary playback. Changed controls, clip replacement, loop changes, cursor jumps and incompatible source rates still require explicit lifecycle restaging. Deterministic tests cover independent time ratio/pitch, reset/seek history, fractional transport, loop/EOF behavior, cache starvation/refill, 44.1→48 and 96→48 conversion, fallback behavior, path switching, owner stage/disarm/replacement lifecycle, native lifecycle configure/release/load/seek/rate/pitch intent and warmed zero-heap processing. Passing these tests establishes a qualified integration boundary; it does not establish fully compensated deck latency, seamless perceptual switching, reviewed listening quality, supported hardware latency or release readiness.

## Musical analysis and editable-grid foundation

BrokeDJ now has bounded JUCE-independent offline rhythm and musical-key analyzers. A background adapter reads supported local audio sequentially and feeds both analyzers from the same decode pass. Rhythm analysis reduces input to a compact onset envelope, estimates BPM and beat-zero phase and publishes metadata only when correlation/phase confidence gates pass. Key analysis uses bounded decimation, fixed Hann-window spectral evidence and major/minor chroma-profile matching. Silence, steady tones and deterministic broadband noise are explicit negative fixtures so neither detector claims musical metadata merely because audio exists. Non-finite input is sanitized, work is capped by configurable duration and cancellation is checked between bounded decoder reads.

Analysis-cache schema v2 stores file size/modification identity and independently optional derived beat/grid/key metadata without placing the raw local source path or filename in its payload. Cache access remains outside the callback. The app starts analysis only after a successful deck load, on a worker pool separate from decode/read-ahead preparation so playback availability does not wait for analysis. Per-deck cancellation tokens prevent a stale result from replacing metadata after rapid track replacement or shutdown.

The editable `BeatGrid` model is also JUCE-independent. It validates a detected grid, permits transactional beat-zero and segment-BPM correction, supports bounded variable-tempo segments inserted at exact beat positions, preserves continuous beat numbering, converts beat↔time in both directions and supplies musical quantization primitives for later hotcue/beat-loop/sync work. The current deck UI displays independently accepted BPM/grid and key metadata; confidence/details live in the tooltip. Manual editing/persistence is intentionally not exposed until the correction workflow and longer-lived library/session ownership are designed. No claim is made that the current detectors are professionally accurate on arbitrary music or that tempo changes are automatically detected.

This still does **not** prove transparent DSP, zero dropouts on real storage/codecs, production-ready key lock, zero clicks on every transition, professional BPM/key accuracy, harmonic-mixing correctness or professional live readiness. Real-file stress, slow-storage behavior, representative music-domain analysis, physical callback deadlines and reviewed listening evidence remain open.

## Effects scope

Target roughly 30–40 different DSP effects across delay/reverb, modulation, beat manipulation and distortion/pitch categories. A preset is not a new effect. Each effect needs bypass/null or reference tests where meaningful, bounded parameters, stable tail handling and listening tests.
